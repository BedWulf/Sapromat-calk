# СОПРОМАТ ОмГТУ — задания №1 и №2 в одном приложении

Единая автономная программа для Windows 10/11 x64: **растяжение–сжатие** и **кручение** четырёхучастного стержня/вала. Создана на основе ранее проверенных вычислительных модулей и **двух оригинальных DOCX-примеров преподавателя**.

## Как использовать

1. На домашней Windows с интернетом установите **Python 3.12 x64**.
2. Распакуйте ZIP; запустите `build_exe.bat` двойным щелчком.
3. Сценарий установит зависимости в `.venv`, проверит вычисления, соберёт один файл и выполнит самопроверку. В случае ошибки он сообщит о ней и не выведет `SUCCESS`.
4. Перенесите на рабочий компьютер **только** `dist\Sopromat_OMGTU.exe`.
5. Запустите EXE, введите ФИО, группу, вариант (например `11-2-23-4`) и откройте нужную задачу. Главный экран передаёт данные титульника обоим модулям.
6. Внутри каждого модуля можно изменить строку исходных данных, схему и ручные данные. Кнопка сохранения DOCX использует непосредственно шаблон преподавателя.

**Для работы приложения на рабочем ПК интернет, Python и Office не требуются.** Word/LibreOffice понадобится только для открытия отчётов DOCX. При старте `--onefile` автоматически распаковывается в `%TEMP%`; нужны права на эту папку. Антивирус организации может блокировать неподписанный EXE — согласуйте его использование с ИТ-отделом.

Если сборка не запускается, откройте PowerShell в корневой папке и выполните `cmd /c build_exe.bat`. Не запускайте архив до распаковки.

## Структура

- `main.py` — единое окно, единые данные титульника, выбор двух задач; подготовлено под будущие №3 и №4.
- `tension/` — расчёт N(z), граничные условия, подбор прямоугольного сечения и редактирование собственной схемы.
- `torsion/` — расчёт Mк(z), реакции, подбор круглого и кольцевого сечений, сравнение веса, пользовательские моменты.
- `teacher_exact.py` — заполнение **оригинальных** Word документов с сохранением таблиц, математических объектов OMML, полей и расположения рисунков.
- `teacher_templates/` — неизменённые DOCX преподавателя; включаются внутрь единого EXE.
- `tests/` — проверка обоих DOCX на совпадение структуры с исходниками и контрольных вычислений.
- `build_exe.bat` — сборка в один EXE.

## Ограничения, о которых важно знать

- Примеры оформления сохранены в своей структуре: **3 страницы у задания №1** и **4 страницы у задания №2** для контрольных вариантов. При очень длинных формулах в пользовательских схемах Word может перенести текст и увеличить число страниц.
- Схемы и эпюры генерируются программно и занимают **те же места и размеры**, что рисунки преподавателя. Полного пиксельного совпадения с его рукописными и растровыми рисунками нет.
- Программа решает линейные стержневые задачи с одной заделкой, а не произвольные пространственные конструкции/статически неопределимые системы.
- В решённом образце кручения на II участке указано **3m**, а рисунок стандартной схемы №11 в приложении имеет другое обозначение. Контрольный пример и стандартная схема поэтому не отождествляются.
- В формульном объекте исходного образца было написано **180 МПа** в тексте проверки даже для [σ]=160/[τ]=90. Генератор заменяет такое число на фактическое допускаемое напряжение; логика оформления не меняется.
- Сборка под Windows выполняется **на Windows**. Linux-версии проекта не равнозначны проверке скомпилированного Windows EXE. Из этой среды проверка собранного Windows-файла невозможна.

## Проверка исходников

На домашней Windows после установки зависимостей:

```powershell
python -m unittest discover -s tests -v
$env:PYTHONPATH='tension'; python -m unittest discover -s tension -p 'test_*.py' -v
$env:PYTHONPATH='torsion'; python -m unittest discover -s torsion/tests -p 'test_*.py' -v
python main.py
```
