# Sapromat-calk — версия 7 (27.10.2026)

**Актуальная версия.** Для стандартной схемы №1–30 граничное условие вычисляется без ввода пользователя. Для своей схемы положение закрепления определяет единственное доступное поле Г.У.: `N(0)` при заделке справа и `N(4l)` при заделке слева. Второе вычисляется из равновесия. Подробности — в разделе «Версия 7» ниже.

Титульный лист формируется с использованием **точного шаблона страницы 2 преподавателя**. Последние два элемента четырёхчастного варианта соответствуют задачам 1, 2, 4–10, первые два — задаче 3. Неизвестные два числа не подставляются автоматически.

Проверка: `python -m unittest discover -v` (30 тестов). Протокол `PROVERKA_V7.md`.

# История проекта — изменения версии 5

**Историческая информация:** В графическом редакторе автоматически показываются **оба** условия `N(0)` и `N(4l)`: одно по свободному торцу, другое из уравнения равновесия. Можно выбрать ручной ввод любого одного значения; несовместимые с силами условия не допускаются. Для пользовательской схемы теперь можно задать координаты сил `z/l` и распределённых нагрузок `от/l` / `до/l`.

**Важное исправление:** при визуальной сверке оригинальных рисунков обнаружены неверные положения сил в схемах **1, 9, 15, 18, 25**, которые исправлены в `core/variants.py`. Прежние числовые тесты не могли обнаружить эти ошибки ввода исходных схем, так как сравнивали расчёт с теми же входными данными. Подробнее: `PROVERKA_V5.md`.

Запуск: `python -m pip install -r requirements.txt`; затем `python -m unittest discover -v` и `python main.py`.

# Расчёт на растяжение-сжатие — версия с вариантами ОмГТУ

## Возможности

- **Ввод данных**: выбор строки 1–30 из приложения 1; флажок «Свои исходные данные» для свободного ввода P, q, l.
- **Схема нагружения**: выбор схемы 1–30 из приложения 2; флажок «Своя схема» для включения ручного редактора.
- **Граничные условия**: автоматически определяются **на свободном торце** по силе, приложенной к нему. Для закреплённого торца нельзя произвольно задавать ноль — там возникает реакция. Можно снять флажок автоматического определения и задать вручную N(0) или N(4l).
- **Титульный лист**: через меню «Титульник» заполните ФИО, группу, полный номер варианта (четыре компонента) и преподавателя. Word-документ содержит пояснения, уравнения, 8 значений N(z), расчёт опасного сечения и прочности, схему и эпюру.

## Запуск

На Windows установите Python 3.10+, в папке проекта выполните:

```bat
pip install -r requirements.txt
python main.py
```

Или используйте `build.bat`, если необходим исполняемый файл (зависит от наличия PyInstaller).

## Проверки

```bat
python -m unittest -v test_variants
```

Контрольный пример (схема №22, P=15 кН, q=15 кН/м) даёт значения 45, 45, 45, 15, 15, 15, 30, 30 кН и b=12 мм, h=24 мм. Обратите внимание: в образце преподавателя q=15 кН/м, **хотя в строке №11 таблицы приложения 1 q=6 кН/м**. Для дословного воспроизведения чисел образца отметьте «Свои исходные данные» и введите q=15.

**Ограничения (относились к прежним версиям)**: с версии 5 пользовательские силы можно размещать произвольно по длине стержня. Для нестандартных схем с неодинаковыми длинами участков потребуется расширение редактора. Встроенные 30 схем перенесены с изображений из приложения 2, поэтому перед сдачей рекомендуется визуально сопоставить выбранную схему с оригиналом. Работа GUI не проверялась в этой среде из-за отсутствия PyQt6; расчётное ядро и Word-экспорт проверены отдельно.

## Версия 4 — независимый аудит вычислений (27.10.2026)

Выбирайте именно эту версию, а не старые `updated-v2/v3`.

### Что исправлено

1. Графический интерфейс: две независимые группы радиокнопок для стороны опоры и выбора вручную заданного Г.У.; иначе переключение одного выбора могло снять другой.
2. Ошибка Word-сохранения `NameError: temp_dir`: удалён вызов `temp_dir.cleanup()` несуществующей переменной. Рисунок формируется в контекстном временном каталоге WordExporter.
3. По задаче №1 преподавателя **основное сечение выбирается только по прочности**. До этой версии программа молча применяла дополнительную и завышенную проверку жёсткости вместо заданного условия. Отдельный флажок в окне входных данных включает одновременный учёт жёсткости при желании.
4. Перемещения W теперь интегрируются точно по каждому интервалу постоянной распределённой нагрузки: `W(z)=∫ N(z)/(E F) dz` от закреплённого конца. Максимум ищется в точках разрыва нагрузок и внутри интервалов там, где `N(z)=0`.
5. Опасное сечение проверяется по обе стороны сосредоточенных сил, включая нагрузки внутри стандартных участков.
6. Word: исправлены преждевременные компенсационные слагаемые в уравнениях участков. В универсальном уравнении используются скобки Маколея, чтобы нагрузка действовала только после координаты её начала.
7. Word: минимальные геометрические размеры ДО округления больше не подменяются размерами ПОСЛЕ округления. Сечение и фактические напряжения в итоговых проверках согласованы.
8. Явные проверки недопустимых координат, отрицательных длин, нулевого модуля упругости, несовместимых граничных условий, выхода за список стандартных размеров преподавателя.

### Проверка на учебных числовых примерах из открытых источников

- [Testbook, круглый стержень](https://testbook.com/question-answer/a-2-m-long-steel-rod-with-20-mm-diameter-experienc--6a197924bd8bbe6fd61c26ef): P=40 кН, L=2 м, d=20 мм, E=200 ГПа → удлинение 1.273 мм.

- Знаки сил и правило построения эпюры: [Penn State Mechanics Map](https://mechanicsmap.psu.edu/websites/6_internal_forces/6-3_axial_torque_diagrams/axial_torque_diagrams.html); нормальные размеры: [Росстандарт, ГОСТ 6636-69](https://protect.gost.ru/gost/details/81770b69-029b-4037-9ef7-a9846c76dfaf).

### Автоматические тесты

### Ограничения

- Изображения всех 30 схем перенесены в библиотеку вручную. Перед сдачей работу нужно сопоставить с исходным приложением преподавателя.
- В v5 добавлен ручной ввод дробных координат сил и интервалов распределённых нагрузок. По-прежнему поддерживается только стержень с одной жёсткой опорой, постоянными E и сечением.
- Расчёт предполагает прямой однородный стержень с постоянной площадью и линейно-упругим материалом; **потеря устойчивости при сжатии не проверяется**.

- Пример преподавателя №22 содержит P=15, q=15, хотя для строки №11 таблицы приложения 1 указано q=6; числа демонстрационного образца требуют *своих исходных данных*.

## Обновление v6 — автоматические граничные условия и проверка результата

**Рекомендуемая версия: v6**. Выберите строку исходных данных 1–30 и схему 1–30. При необходимости включите отдельные режимы «Свои исходные данные» или «Своя схема». Сторона закрепления для стандартной схемы выбирается автоматически.

Поставьте галочку «Автоматически определять по схеме» — программа получит условие на свободном конце и автоматически найдёт второе из равновесия, а также покажет реакцию опоры. Чтобы ввести N(0) или N(4l) самостоятельно, снимите галочку и выберите **одно** из двух условий. Если условие физически противоречит приложенным нагрузкам на свободном конце, программа откажется вычислять вместо молчаливой выдачи ошибочной эпюры.

В программе исправлено отображение множителей P и q на схеме, а также очистка устаревших результатов при изменении исходных данных. Подробности и область применимости: `PROVERKA_V6.md`.

## Версия 7 — граничные условия и титульный лист

**Стандартные схемы №1–30:** положение закрепления и известное условие
определяются автоматически из выбранной схемы и нагрузок. Заполнять N(0)
или N(4l) вручную НЕ нужно и нельзя.

**Своя схема:** выберите закрепление слева или справа. По умолчанию программа
сама вычислит условие на свободном торце. Чтобы задать его вручную, снимите
флажок «Граничное условие автоматически по свободному торцу». Появится ровно
одно поле N(4l) при опоре слева или N(0) при опоре справа; второе значение
рассчитывается автоматически. Введённое условие проверяется по нагрузкам.

**Титульный лист:** «Титульник» → «Редактировать титульник…». Экспорт
использует шаблон страницы 2 преподавателя из `export/assets/teacher_title_template.docx`.
Четырёхчастный вариант трактуется по странице 1 методички: **два первых
числа** относятся к задаче №3; **два последних** — к задачам №1, 2, 4–10.
Программа заполнит последние два числа и оставит первые два пустыми,
пока их не введёт пользователь.

Проверка: `python -m unittest discover -v`. Протокол — `PROVERKA_V7.md`.
